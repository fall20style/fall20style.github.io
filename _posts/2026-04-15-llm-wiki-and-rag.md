
## 1. 핵심 개념: '지식의 컴파일'

* 기존 RAG: 질문할 때마다 원본 뒤지는 '오픈북 테스트'임. 비효율적이고 지식 안 쌓임.
* LLM Wiki: 정보를 읽고 핵심만 뽑아 마크다운(.md)으로 정리해두는 '학습 노트'임. 나중엔 정리된 노트만 보면 돼서 속도 빠름.

## 2. 시스템 구조 (3계층)

* Raw Sources: 수정 안 하는 원본 데이터(논문, 기사, 로그 등) 보관함.
* Wiki Layer: LLM이 직접 쓰고 수정하는 지식 정리 공간. 요약본, 인물 사전, 개념 정의 파일들로 구성됨.
* Schema (Instructions): 위키 정리 규칙 파일(예: CLAUDE.md). 폴더 구조, 링크 거는 법 등을 LLM에게 지시함.

## 3. 구현 워크플로우

   1. Ingest (입력): 새 문서를 특정 폴더에 넣음.
   2. Process (처리): LLM 에이전트(Claude Code 등)가 원본 읽고 위키 파일 생성/수정함.
   3. Link (연결): 관련 문서끼리 내부 링크([[문서명]]) 걸어서 지식망 형성함.
   4. Lint (검증): 중복 내용 합치고 모순되는 정보 있는지 주기적으로 체크함.

## 4. 기대 효과

* 비용 절감: 매번 긴 원본 안 읽어도 돼서 토큰 사용량 줄어듦.
* 가독성: 벡터 DB와 달리 사람이 직접 읽고 수정 가능해서 관리 편함.
* 성장형 지식: 데이터가 쌓일수록 단순 저장이 아닌 정교한 지식 체계로 진화함.

카파시(Karpathy) 스타일의 LLM Wiki 폴더 구조와 실제 마크다운 파일 예시임.


## 구성하기

### 1. 전체 폴더 트리 (tree 구조)

지식의 원본(raw), 정리본(wiki), 규칙(schema)을 철저히 분리함.

```
/my-llm-wiki/
├── 00_schema/          # LLM 행동 지침
│   └── CLAUDE.md       # 위키 작성 가이드 (필수!)
├── 01_raw/             # 수정 안 하는 원본 데이터
│   ├── article_01.pdf
│   └── meeting_note.txt
├── 02_wiki/            # LLM이 직접 쓰고 관리하는 영역
│   ├── concepts/       # 주요 개념 정리
│   │   └── RAG.md
│   ├── entities/       # 인물, 단체, 프로젝트
│   │   └── Andrej_Karpathy.md
│   └── index.md        # 전체 위키 대문
└── scripts/            # 위키 업데이트용 파이썬 코드 등
```

------------------------------

### 2. 핵심 파일 예시

#### 00_schema/CLAUDE.md (LLM용 지침)
에이전트가 위키를 수정할 때 지켜야 할 "법전"임.

# Wiki Editing Rules1. 모든 파일은 마크다운(.md) 형식을 사용함.
2. 새로운 개념이 나오면 `[[개념명]]` 형태로 내부 링크를 생성함.
3. 원본 데이터(`01_raw/`)를 인용할 때는 항상 출처를 명시함.4. 기존 문서와 내용이 겹치면 삭제하지 말고 정보를 통합(Merge)함.

####  02_wiki/concepts/RAG.md (정리된 지식)
LLM이 원본을 읽고 스스로 컴파일한 결과물임.

### RAG (Retrieval-Augmented Generation)

- **정의**: 외부 지식을 검색하여 LLM의 답변 품질을 높이는 기술임.
- **특징**: 실시간 정보 반영에 유리하나, 대규모 데이터 처리 시 토큰 비용이 발생함.
- **관련 링크**: [[LLM_Wiki]] (RAG의 한계를 보완하는 대안적 접근법임)

### 3. 실제 워크플로우 (명령 예시)

터미널에서 Claude Code 같은 에이전트에게 이렇게 시키면 됨.

```
"내 01_raw/ 폴더에 새로 넣은 '카파시 트윗.txt' 읽어줘. 그 내용을 바탕으로 02_wiki/에 있는 'LLM_Wiki' 문서를 업데이트해주고, 새로 나온 인물은 entities/ 폴더에 추가해줘."
```

이렇게 하면 LLM이 알아서 파일을 열고, 내용을 요약해서 마크다운으로 '컴파일'함.
Obsidian(옵시디언) 앱으로 이 폴더를 열면 모든 문서가 시각적으로 연결되어 보임. 바로 폴더 세팅 시작해볼 거임?
