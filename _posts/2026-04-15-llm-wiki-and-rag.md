
## 1. 핵심 개념: '지식의 컴파일'

* 기존 RAG: 질문할 때마다 원본 뒤지는 '오픈북 테스트'임. 비효율적이고 지식 안 쌓임.
* LLM Wiki: 정보를 읽고 핵심만 뽑아 마크다운(.md)으로 정리해두는 '학습 노트'임. 나중엔 정리된 노트만 보면 돼서 속도 빠름.

## 2. 시스템 구조 (3계층)

* Raw Sources: 수정 안 하는 원본 데이터(논문, 기사, 로그 등) 보관함.
* Wiki Layer: LLM이 직접 쓰고 수정하는 지식 정리 공간. 요약본, 인물 사전, 개념 정의 파일들로 구성됨.
* Schema (Instructions): 위키 정리 규칙 파일(예: CLAUDE.md). 폴더 구조, 링크 거는 법 등을 LLM에게 지시함.

## 3. 구현 워크플로우

   1. Ingest (입력): 새 문서를 특정 폴더에 넣음.
   2. Process (처리): LLM 에이전트(Claude Code 등)가 원본 읽고 위키 파일 생성/수정함.
   3. Link (연결): 관련 문서끼리 내부 링크([[문서명]]) 걸어서 지식망 형성함.
   4. Lint (검증): 중복 내용 합치고 모순되는 정보 있는지 주기적으로 체크함.

## 4. 기대 효과

* 비용 절감: 매번 긴 원본 안 읽어도 돼서 토큰 사용량 줄어듦.
* 가독성: 벡터 DB와 달리 사람이 직접 읽고 수정 가능해서 관리 편함.
* 성장형 지식: 데이터가 쌓일수록 단순 저장이 아닌 정교한 지식 체계로 진화함.
