- gemini CLI가 core dump를 분석하고 보고서를 만들어 줌.

### gdb에서 bt full 결과를 bt.txt에 저장하기

``` bash
gdb -ex "bt full" -ex "quit" target core > bt.txt
```

#### bt.txt 내용
```
Reading symbols from target...
[New LWP 14973]
Core was generated by `./target'.
Program terminated with signal SIGABRT, Aborted.
#0  0x00007f4096d1500b in ?? ()
#0  0x00007f4096d1500b in ?? ()
No symbol table info available.
#1  0x0000000000000000 in ?? ()
No symbol table info available.
```

### bt.txt를 gemini CLI에 전달하고 분석 > 결과가 stdout으로 출력
``` bash
cat bt.txt | gemini "이 로그에서 세그멘테이션 폴트가 발생한 코드 지점을 찾아줘..."
```

### bt.txt를 gemini CLI에 전달하고 분석 > 결과를 result.txt로 저장
``` bash
cat bt.txt | gemini "이 로그에서 세그멘테이션 폴트가 발생한 코드 지점을 찾아줘..." > result.txt
```

### 표준에러를 버리고 실행
```
cat bt.txt | gemini "이 로그에서 세그멘테이션 폴트가 발생한 코드 지점을 찾아줘..." 2>/dev/null > result2.txt
```

### 표준에러를 버리고 실행, 120초가 지나면 Timeout
```
cat bt.txt | timeout 120s gemini "이 로그에서 세그멘테이션 폴트가 발생한 코드 지점을 찾아줘..." 2>/dev/null > result.txt
```

### 표준에러를 버리고 실행, 120초가 지나면 Timeout error.log출력

```
cat bt.txt | timeout 120s gemini "분석 요청..." 2>/dev/null > result.txt || [ $? -eq 124 ] && echo "오류: 2분 초과로 중단됨..." >> error.log
```



#### result.txt 내용
- 마크다운 형태로 출력됨
- 같은 dir의 다른 파일을 읽고 분석을 한 것 같다. 

```
I will start by examining the source code in `overflow.c` and checking the `bt.txt` and `CRASH_REPORT.md` files to gather more information about the crash.
제공해주신 로그와 소스 코드를 분석한 결과, 프로그램이 중단된 지점과 원인은 다음과 같습니다.

### 1. 발생 지점
*   **파일:** `overflow.c`
*   **함수:** `vulnerable_function`
*   **문제의 코드 (원인):** 10라인의 `strcpy(buffer, input);`
*   **실제 중단 시점:** `vulnerable_function`이 종료되는 시점(13라인 근처)

### 2. 상세 원인 분석
이 오류는 단순한 세그멘테이션 폴트가 아니라, **스택 버퍼 오버플로우(Stack Buffer Overflow)**에 의한 보안 메커니즘 작동으로 발생한 `SIGABRT` (Aborted)입니다.

1.  **오버플로우 발생:** `vulnerable_function`에서 10바이트 크기의 `buffer`에 약 42바이트 길이의 `too_long_string`을 `strcpy`로 복사하면서, `buffer`의 경계를 넘어 스택 메모리가 오염되었습니다.
2.  **스택 가드(Stack Canary) 파손:** 이 과정에서 함수의 복귀 주소와 스택 보호를 위한 '카나리(Canary)' 값이 덮어씌워졌습니다.
3.  **오류 탐지 및 종료:** 함수가 끝날 때(13라인) 컴파일러가 삽입한 스택 보호 로직(`__stack_chk_fail`)이 카나리 값의 변조를 감지하고, 프로그램을 안전하게 강제 종료(`SIGABRT`)시켰습니다.

`CRASH_REPORT.md`의 콜 스택에서도 `__stack_chk_fail`이 호출된 후 `vulnerable_function`에서 멈춘 것을 확인할 수 있습니다. 이를 해결하려면 `strcpy` 대신 `strncpy`를 사용하거나 버퍼 크기를 체크하는 로직을 추가해야 합니다.
```
