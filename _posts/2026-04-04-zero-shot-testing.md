
## 1. Zero-shot Testing 개념

* 사전 학습/예시 없음: 모델한테 "이런 식으로 테스트 짜줘"라고 예시(Example)를 단 하나도 안 보여주는 방식.
* 깡성능 테스트: 모델이 원래 알고 있던 지식만으로 바로 결과물을 내놓음.
* 즉석 대응: 새로운 코드나 상황을 던져줘도 별도 가이드 없이 즉시 테스트 케이스를 뽑아냄.

## 2. 하니스 엔지니어링에서의 특징

* 코드 자동 분석: src/main.rs 소스만 보고 "아, 이건 더하기 기능이네?"라고 스스로 파악함.
* 데이터 추론: 구조체 필드명(a, b)이랑 타입(i32) 보고 넣을 값을 알아서 결정함.
* 엣지 케이스 생성: 시키지 않아도 음수나 큰 숫자, 잘못된 문자열 같은 예외 상황을 테스트에 포함함.

## 3. 장점과 단점

* 속도 개꿀: 예제 코드(Few-shot)를 작성할 시간이 필요 없어서 자동화 속도가 압도적임.
* 편향 제거: 개발자가 놓치기 쉬운 부분을 LLM이 제삼자 입장에서 던져줌.
* 정확도 변수: 모델 성능에 따라 엉뚱한 테스트 코드를 짤 수도 있음. (검토 필요)

## 요약
- 설명이나 예시 생략하고 코드만 던졌는데, 모델이 알아서 테스트 하니스 작성
