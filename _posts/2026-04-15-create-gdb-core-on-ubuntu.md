### Crash가 발생하는 코드 작성
``` c
#include <stdio.h>
#include <string.h>

void process_data(char *input) {
    // 버그: input이 NULL인지 확인하지 않음
    int len = strlen(input); 
    printf("데이터 길이: %d\n", len);
}

int main() {
    char *data = NULL;
    process_data(data); // 여기서 세그멘테이션 폴트 발생
    return 0;
}
```

### gcc로 컴파일, ulimit 지정, coredump 생성 시도

:~/work/test_gcc_llm$ ulimit -c unlimited

### Crash Analysis Walk-through
To identify the cause of the crash, the following steps were taken:

1. **Environment Check**: Confirmed the presence of the executable (`target`), the core dump (`core`), and the source code (`target.c`).

2. **GDB Execution**: Ran GDB in batch mode to analyze the core dump:
    -   Command: `gdb ./target core --batch -ex "bt" -ex "list"`
    -   **Backtrace (`bt`)**: Revealed the crash occurred in `strlen` called from `process_data` at `target.c:6`.
    -   **Context**: Showed that `process_data` was called from `main` at `target.c:12` with an input value of `0x0` (NULL).
3. **Source Code Inspection**: Examined `target.c` to verify the logic.
    -   Found that `main` explicitly initialized `data` to `NULL` and passed it to `process_data`.
    -   Confirmed `process_data` lacked a safety check before using the pointer.
4. **Documentation**: Created `CRASH_REPORT.md` with the findings and a recommended fix.
